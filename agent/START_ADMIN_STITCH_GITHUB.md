## المصدر — GitHub أولًا

1. افتح GitHub وابحث في مستودعات الحساب الموصول عن Repository اسمه **`UI-UX-V01`**. إذا أعطيتك عنوان المستودع أو كان موجودًا بالفعل في Workspace، استخدم هذا العنوان الدقيق ولا تفترض اسم مالكه. إذا لم يتوفر وصول GitHub، اذكر المشكلة واطلب ربطه، ولا تزعم أنك استنسخته.
2. استنسخ المستودع باستعمال الصلاحيات الممنوحة، وافحص `git remote -v`, `git status`, `git branch -a`, `git log -5 --oneline`. **لا تحذف ملفات أو تاريخًا موجودًا.**
3. ابدأ بـ`README.md` ثم `AGENTS.md` ثم `agent/START_ADMIN_STITCH_GITHUB.md`، وتابع قراءة بقية المصادر أدناه.
4. نفّذ `python scripts/verify_pack.py` من جذر المستودع؛ لا تبدأ التصميم قبل إثبات وجود **638** ملف شاشة للإدارة و**25** ملف وحدات، و**122** ملف متجر، وغياب مسارات/معرّفات مكررة.
5. في حال المستودع غير مرفوع أو فارغ، توقف عن ادعاء القراءة؛ استخدم ملف ZIP الأصلي فقط إذا كان حاضرًا بالفعل ومصرحًا باستعماله، وسجّل المصدر المستخدم.

## حلقة تنفيذ إجبارية — ملف ← شاشة ← فحص ← حفظ

لكل شاشة `ADM-XXXX` لم يثبت اكتمالها بالفعل:

1. اقرأ ملف `02_ADMIN_PANEL/MODULE_PROMPTS/<module>.md` الكامل المرتبط بالوحدة. احتفظ بسياقه أثناء العمل داخل الوحدة، وأعد قراءته إذا انقطع السياق.
2. اقرأ **كامل** ملف الشاشة المحددة في `02_ADMIN_PANEL/SCREEN_PROMPTS/<file>.md`: Screen ID وRoute وHierarchy وRequired UI Composition وInteractive Rules وPrototype Connections ونص `PASTE INTO GOOGLE STITCH`.
3. أنشئ التصميم الفعلي داخل Stitch بمقاس Desktop 1440px مع حالات التفاعل الأساسية والمحمول/التابلت عند طلب ملف الشاشة. انقل المعنى والتفاصيل كلها إلى أداة التصميم؛ إذا قيّد حجم الطلب استخدام النص كاملًا، قسّمه منطقيًا إلى طلب إنشاء ثم طلب Refinement، دون إسقاط المتطلبات.
4. استخدم بيانات عربية تجريبية مناسبة للخشب والورد: نقش أسماء وتخصيصات، معاينة إثبات النقش، الوصفات والتجميع، تخزين ورد FEFO، أحجام وتركيبات، شحن الرياض والوقت المحدد، منتجات SAR، حالات استثناء وصلاحيات. كل أمثلة الأسعار والطلبات **بيانات تصميم وهمية**.
5. راجع النتيجة بعينك أو بواسطة صورة/معاينة موثقة عائدة من Stitch: دقة العربية RTL، القراءة، المحتوى الوظيفي الحقيقي، التفاعل المطلوب، استمرارية التنقل، حالة Empty/Loading/Error/Denied، ملاءمة الوحدة وعدم تكرار نفس الشكل. أصلح بالـEdit/Refine حتى 3 محاولات عند الإمكان.
6. لا تكتب `COMPLETED` قبل وجود `stitch_project_id`, `stitch_screen_id`, `stitch_screen_url` ونجاح QA. إذا امتنع Stitch عن إرجاع بعض المعرفات أو الروابط، سجّل الحالة كما هي ولا تخترعها؛ استخدم `BLOCKED` أو `QA_FAILED` وأضف السبب.
7. حدّث `tracking/admin_execution_ledger.json` بدقة (`status`,`qa_status`,`attempts`,`last_error`,`updated_at`) بعد كل شاشة. احفظ نسخة دائمة عبر commit/push **فقط** إذا كانت صلاحية GitHub متاحة. إذا لم تكن، احفظ ملفًا محليًا قابلًا للتنزيل وحدد طريقة الاستئناف.
8. انتقل للشاشة التالية دون طلب إذن إضافي داخل جلسة تنفيذ فعالة، مع الحفاظ على حدود API والصلاحيات. عند التوقف، اترك تقريرًا قابلًا للاستكمال من آخر شاشة غير مكتملة.

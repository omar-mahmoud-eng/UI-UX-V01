# AG02 Capability Ownership & Medusa v2 Reuse Matrix (Remediated)

**System**: CommerceOS Modular Monolith  
**Architecture Scope**: **Single-Store Self-Hosted Deployment per Client**  
**Framework Version**: Medusa v2 (`@medusajs/framework`)  
**Guiding Invariant**: **Medusa-First Architecture (Constitution Principle III)** — Reuse native official modules, workflows, and provider interfaces. Zero duplication of core commerce engines. Zero forks of Medusa core. Zero shadow inventory balances.

---

## 1. Capability Ownership Matrix

| Domain Capability | Default Owner / Provider | Status | Official Medusa v2 Extension Point / API | Data Ownership & Boundary | Cross-Module Integration Contract | Justification & Architectural Tradeoffs |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Product Catalog & Hierarchy** | Medusa Product Module (`@medusajs/medusa/product`) | **Native OOTB** | `ProductService`, Data Models (`Product`, `ProductVariant`, `ProductCategory`, `ProductCollection`). | Schema: `product_*` tables. Complete ownership of catalog hierarchy, options, and tags. | Linked to Custom Modules via `defineLink`. Queried via `RemoteQuery`. | Reusing native eliminates maintaining complex variant permutations, option matrices, and category trees. Custom attributes live in structured `metadata` or linked models. |
| **Multi-Currency Pricing & Price Lists** | Medusa Pricing Module (`@medusajs/medusa/pricing`) | **Native OOTB** | `PricingService`, `PriceList`, Rule-based pricing engines, Contextual Pricing (e.g. currency: `SAR`, customer group). | Schema: `price_*` tables. Single source of truth for base prices and overrides. | Price calculation injected into Cart and Line Items automatically via core pricing workflows. | Native pricing supports rule-based discounts, VIP tiers, and multi-currency out of the box. Zero need for custom pricing calculators. |
| **Promotions, Discounts & Campaigns** | Medusa Promotion Module (`@medusajs/medusa/promotion`) | **Native OOTB** | `PromotionService`, Campaign rules, Promo codes, Buy-X-Get-Y rules, automatic promotions. | Schema: `promotion_*` tables. Owns promotion budgets, usage limits, and application criteria. | Consumed during cart calculation via `computePromotionWorkflow`. | Prevents double-discount vulnerabilities and race conditions during coupon redemptions. |
| **Cart & Session Management** | Medusa Cart Module (`@medusajs/medusa/cart`) | **Native OOTB** | `CartService`, `addToCartWorkflow`, `updateCartWorkflow`, Cart completion pipeline. | Schema: `cart_*` tables. Holds ephemeral shopper state until conversion. | Links to Customer, Shipping Address, and Payment Collection. | Native carts manage line items, tax lines, adjustment lines, and shipping methods in a single cohesive transactional entity. |
| **Inventory & Reservations** | Medusa Inventory & Stock Location Modules | **Native OOTB** | `InventoryItem`, `InventoryLevel`, and `ReservationItem`. Stock reservations created via `createReservationsWorkflow`. | Schema: `inventory_item_*`, `stock_location_*`. Sole source of truth for inventory and holds. | Linked to Product Variants via Medusa official link: `productVariantInventoryItemLink`. | **Zero Shadow Stock in Redis**: Medusa manages atomic reservations during checkout. Overselling is prevented at the database level by transactional reservation records. |
| **Customer Identity & Profiles** | Medusa Customer Module (`@medusajs/medusa/customer`) | **Native OOTB** | `CustomerService`, Customer Groups, Addresses. | Schema: `customer_*` tables. Dedicated customer profile store. | Linked to Auth Module for credentials, linked to CRM module via Module Link. | Single-store customer identity. Access control enforces that customers can only query their own data (`customer_id` match). |
| **Authentication & Sessions** | Medusa Auth Module (`@medusajs/medusa/auth`) | **Native OOTB** | `AuthService`, Auth Providers (`emailpass`, OAuth, SMS OTP via custom provider). | Schema: `auth_identity_*` tables. | **Checkout & Order Lifecycle** | Medusa Order Module (`@medusajs/medusa/order`) | **Native OOTB** | `OrderService`, `completeCartWorkflow`, Order Change, Returns, Fulfillments, Claims. | Schema: `order_*` tables. Immutable financial order record upon creation. | Orchestrated through Medusa's official `completeCartWorkflow`. | On checkout failure, Medusa invokes workflow compensation: cancels authorized payments OR issues refunds if payment was captured by the provider. |
| **Payment Gateway Integration** | Medusa Payment Module (`@medusajs/medusa/payment`) | **Provider API** | `PaymentProvider` interface (`authorizePayment`, `capturePayment`, `refundPayment`, `cancelPayment`). | Schema: `payment_*` tables. Tracks payment sessions and transactions. | Linked to Cart during checkout; linked to Order upon completion. | Reusable provider architecture allows plugging Moyasar / PayTabs / Tamara without altering checkout workflow logic. |
| **Fulfillment & Logistics** | Medusa Fulfillment Module (`@medusajs/medusa/fulfillment`) | **Provider API** | `FulfillmentProvider` interface (`calculateShippingRates`, `createFulfillment`, `cancelFulfillment`). | Schema: `fulfillment_*` tables. | Linked to Shipping Options and Order line items. | Standardizes integration with KSA delivery couriers (SMSA, Aramex, Torod, Jahez) through uniform fulfillment interfaces. |
| **Admin Dashboard UI** | Medusa Admin (`@medusajs/admin`) | **Native + Extensions** | Vite-powered React extension points (`Widget`, `Route`, `Setting`). `@medusajs/ui`. | Medusa Admin bundles standard commerce UI; extensions render custom modules. | Extensions query backend API routes authenticated with Admin JWT / session cookies. | Single-store role-based access control (Admin, Member). | **Storefront Web App** | Medusa Next.js Starter (`medusajs/nextjs-starter-medusa`) | **GitHub Starter Repo** | Next.js App Router, Server Components (RSC), `@medusajs/js-sdk`. | Server-side rendered; stateless with publishable API key authentication. | Communicates exclusively with Medusa Store API over HTTP/REST. | Fully typed client SDK, optimized for Web Vitals (LCP, INP, CLS) and responsive RTL/LTR layouts. |
| **Background Jobs & Event Bus** | Medusa Event Bus & Workflow Engine | **Native OOTB** | `@medusajs/event-bus-redis`, Scheduled Jobs (`medusa.defineJob`), Workflows. | Redis streams / BullMQ backing queues. | Subscribers listen to emitted events (`order.placed`, `customer.created`). | Decouples immediate HTTP responses from asynchronous side-effects (e.g., sending emails, queuing invoice generation). |

## 2. Approved CommerceOS Custom Bounded Contexts (Gaps)

Where native Medusa v2 does not provide domain functionality required by CommerceOS, the following isolated custom modules are approved in design:

| Custom Domain Context | Status | Architectural Design & Official Medusa Building Blocks | Data Ownership & Storage Boundary | Cross-Module Integration Contract | Rationale & Guardrails |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **CMS & Page Builder** | **Approved Custom Module** | Built as Medusa Domain Module using `@medusajs/framework` Service Factory. Exposes Admin UI widget for drag-and-drop page composition. | Schema: `cms_pages`, `cms_sections`, `cms_blocks`. Completely isolated schema; zero core foreign keys. | Linked to Categories/Products via `defineLink([ProductModule.linkable.product, CmsModule.linkable.cmsBlock])`. Queried by Storefront via `RemoteQuery`. | Medusa core is headless and has no native content management or visual block builder. Must sanitize all HTML/JSON to prevent stored XSS. |
| **Product Personalization (Customizer)** | **Approved Custom Module** | Module for custom bakery/flower cakes, card messages, engraving options, custom image uploads. | Schema: `customizer_configurations`, `customizer_options`, `customizer_attachments`. | Attached to Cart Line Item through `line_item.metadata` or custom Module Link. Emits customizer validation step in `addToCartWorkflow`. | Native products allow fixed variants, but dynamic customization requires dynamic pricing adjustments and asset attachments. |
| **CRM, Loyalty & Customer Tiers** | **Approved Custom Module** | Points ledger, referral tracking, customer engagement scores. | Schema: `loyalty_accounts`, `loyalty_ledger_transactions`, `tier_milestones`. | Subscribes to `order.placed` via Event Subscriber. Links `customer_id` to `loyalty_account` via `defineLink`. | Keeps core customer module lean and unencumbered by marketing reward mechanics. Points redemption acts as an authorized custom promotion. |
| **Saudi ZATCA E-Invoicing (Phase 2)** | **Approved Custom Plugin Design** | Background Worker Workflow triggered on `order.payment_captured`. Generates compliant UBL 2.1 XML, signs with cryptographic stamp, computes invoice hash chain. | Schema: `zatca_invoices`, `zatca_audit_logs`. Stores certified XML, UUID, hash, and clearance status. | Linked to Medusa Order via `defineLink([OrderModule.linkable.order, ZatcaModule.linkable.zatcaInvoice])`. | Legal requirement for Saudi commercial entities. Designed as an asynchronous background job; full compliance requires formal sandbox testing and ZATCA compliance checks. |
| **Analytics & Reporting Read-Model** | **Approved Custom Module** | Asynchronous projection / Materialized View for merchant sales dashboards, conversion funnels, and inventory velocity. | Schema: `analytics_daily_sales`, `analytics_product_velocity`, `analytics_customer_cohorts`. | Consumes Redis domain events asynchronously. Zero write-load on live OLTP checkout tables. | Keeps operational PostgreSQL database responsive. Real-time OLAP queries must never lock active cart/order rows. |

## 3. Strict Prohibitions & Anti-Patterns

1. **PROHIBITED: Forking Medusa Core**: Modifying files inside `@medusajs/*` is strictly forbidden. All customizations must be achieved via Modules, Module Links, Workflows, Plugins, and Admin Extensions.
2. **PROHIBITED: Shadow Inventory / Order / Price Engines**: Creating parallel custom databases for orders, carts, prices, or inventory (including Redis-based inventory counters) is an automatic architectural failure.
3. **PROHIBITED: Modifying Native Medusa Schema for SaaS Multi-Tenancy**: CommerceOS is single-store self-hosted per client. Adding `tenant_id` or RLS policies to Medusa core tables is strictly prohibited.
4. **PROHIBITED: Direct SQL Cross-Schema Joins**: Joining `product` directly with `cms_page` via raw SQL without going through Medusa's `RemoteQuery` or Module Link violates bounded-context encapsulation.

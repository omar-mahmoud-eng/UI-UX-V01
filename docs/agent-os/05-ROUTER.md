# 05 — Deterministic router and precedence for two upstream frameworks

## Priority
Latest explicit human instruction, safety and tool approval > CommerceOS AGENTS + constitution + active gate > verified pinned official APIs > installed Superpowers and Spec Kit workflows > local Medusa domain playbooks. Conflicts MUST be reported by file/line, not silently resolved by skipping tests or asking the agent to improvise.

## Route by intent BEFORE editing
| Input | First applicable process | Second / local skill | Required proof |
| --- | --- | --- | --- |
| New feature / concept | Superpowers brainstorming | Spec Kit specify/clarify/plan/checklist/tasks/analyze | approved requirements+tests |
| Bug, crash, build fail | Superpowers systematic-debugging | local debug-triage, Medusa domain | reproducible fault, hypothesis and regression |
| Implement approved task | Superpowers TDD | local domain skill, Spec Kit implement only within gate | actual RED/GREEN and E2E |
| More than one independent feature | Superpowers dispatching-parallel-agents | owner/worktree allocator | isolation and merge regression |
| Code review | Superpowers requesting/receiving-code-review | security-audit + QA evidence | diff + independent checks |
| Finish stage | Superpowers verification-before-completion | Spec Kit converge, stage gate rubric | fresh test outputs, stop |
| Need skill improvement | Superpowers writing-skills | learning-loop + new holdout | before/after behavior evidence |
| New dependency/provider | supply chain review | Medusa capability mapping + ADR | licensed, versioned, approved |

## No competing sources of truth
Spec Kit owns canonical files in specs/<feature>/spec.md, plan.md, tasks.md. Superpowers writing-plans MAKES their steps precise (file paths, signatures, tests), not a second authoritative tasks document. The issue/task gate still selects ONE stage per session. Spec Kit converge checks coverage, not the safety test pass itself.

## Active context handshake
Agent emits: stage, git SHA, exact read files, external version pages, skills selected and why, expected changed paths, permission/test risks and stop point. Read full root rules, constitution and current spec/task; load only relevant domain docs. Do NOT flood context with all domain plans on every interaction.

## Handoff
Task status PASS/FAIL/BLOCKED/NOT_RUN, tests commands/exits, reviewer, unresolved gaps, next allowed action. Implement stage is never auto-authorized by an installed Superpowers or Spec Kit skill.

## Antigravity
Spec Kit with agy creates hyphenated slash skills (e.g., /speckit-specify). Other agent guides may show dot form. Use actual installed skill names, not memory; verify tool permissions. Superpowers Antigravity starts by skill discovery, not a guaranteed SessionStart hook.
